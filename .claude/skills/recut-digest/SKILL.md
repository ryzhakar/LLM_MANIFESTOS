---
name: recut-digest
description: "Apply one diagnosed change, one demand or one sentence, to a digest or a stack digest and record the new cut. \"re-cut the digest\", \"apply the hypothesis\", \"cut two\", \"make the one change\", or a hypothesis record written for a cut whose digest does not exist yet."
---

<take-the-hypothesis>
Read the hypothesis record, the file `evals/<slug>/cut-<n>/hypothesis.md` naming the one change the next cut makes, whole; never re-cut without one.
Read the digest, the plain text a small model carries in place of a manifesto or a stack of manifestos, whole; never read a summary of it.
</take-the-hypothesis>

<apply-one-change>
Change the one demand or the one sentence the hypothesis names, by rewriting, adding, moving, or deleting it; never change a second.
Hold every other sentence as it stands, character for character; never touch one while the first change is in.
Write the changed sentence as the `write-digest` skill writes one, with Strunk applied and the boundary, the place where the demand stops applying, folded in; never write it another way.
Write a changed stack sentence as the `write-stack-digest` skill writes one, with its object named; never leave it unscoped.
</apply-one-change>

<check-the-change>
Check the changed sentence against the manifesto's full text, or against the member digests for a stack, the demand present and nothing imported; never check against memory of the text.
Keep the file header-free and under the word limit the `write-digest` skill sets, or the `write-stack-digest` skill sets for a stack; never let a change push it over.
</check-the-change>

<save-the-cut>
Save the digest over its own path; never save a cut under a second name.
Save the cut record, holding the cut number, its parent, the digest's hash, the hypothesis, and the exact old and new sentence, through the `write-eval-record` skill; never leave a cut unrecorded.
</save-the-cut>
