## 1. Steps, candidate source to archived entry

1. Discovery and selection.
   - Supplied sources come from the stakeholder as URLs: S-01 blog post, S-02..S-05 YouTube talks. Discovered sources in the dump: D-01 and D-02 are linked from S-01's body, D-03 was found independently (DUMP/README.md:38). They sit in DUMP/secondary/D-0N and are labelled "discovered (not supplied)". Records: DUMP/README.md (`## primary/`, `## secondary/`), DUMP/index/sources.md.
   - Licence flags are in DUMP/README.md `## Licensing and redistribution flags`.
2. Fetch.
   - Text page: raw HTML kept when small (DUMP/primary/S-01-raw.html, 35,634 bytes), article text extracted by a stdlib script (usage in section 2), then DUMP/primary/S-01.txt carries a header (ID, TITLE, AUTHOR, YEAR, URL FETCHED, EXTRACTION METHOD). The script does not write that header.
   - Secondary texts. D-01 is a PDF: original kept byte-for-byte, text from `pdftotext -layout` into DUMP/secondary/D-01/D-01.txt with a header (DUMP/README.md:42; EXTRACTION METHOD at line 6 of D-01.txt). D-02 and D-03 are HTML pages: the original HTML is kept and the text comes from `extract_D-02.py` / `extract_D-03.py` into DUMP/secondary/D-02/D-02.txt and DUMP/secondary/D-03/D-03.txt with the same header (EXTRACTION METHOD at line 6 of each; DUMP/README.md:43, :45); the D-02 PDF is held out of the repo (DUMP/README.md:44). No OCR; scanned pages stay unread (DUMP/README.md:126).
   - Video: metadata JSON, audio (m4a), video (mp4, height <= 1080) and supplementary captions (vtt) into SCRATCH/{meta,audio,video,captions}; a trimmed metadata JSON goes to DUMP/primary/S-0N-<id>/<id>-metadata-trimmed.json. Audio and video are not stored in the repo.
3. Transcription. MacWhisper CLI `mw` on the m4a, two native outputs per video (srt, txt), model parakeet-pro:nvidia_parakeet-v3, language en, one run at a time. Copied unchanged to DUMP/primary/S-0N-<id>/<id>-transcript.srt and `.txt` with a sidecar `<id>-transcript-provenance.txt`. S-02 sidecar fields (lines 1-19): ID, VIDEO ID, TITLE, CHANNEL, UPLOAD DATE, DURATION, URL, SOURCE AUDIO (path, bytes, sha256), TRANSCRIBER, MODEL, LANGUAGE, COMMANDS, DATE, TRANSCRIPT srt (sha256, cues, last cue end), TRANSCRIPT txt (sha256, words), STATUS. STATUS rule in code: SCRATCH/work/finalize.py:46 `status='FULL' if (abs(gap)<=60 and run<=3) else 'PARTIAL'` (finalize.py:47 builds the PARTIAL reason from the last cue end, the duration and the longest repeat); that script covers S-02..S-04 only. STATUS thresholds as recorded in reports and a sidecar: "longest consecutive identical cue run ... below the >3 threshold" (SCRATCH/reports/transcribe.md:55) and "within the 60 s threshold" for the gap between last cue end and audio end (SCRATCH/reports/transcribe-sc1guyo5Rso.md:23); the S-05 sidecar line 22 reads `STATUS: FULL (last cue ends within 60 s of audio duration; longest run of identical consecutive cues is 2)`. YouTube captions are never the transcript.
4. Frame extraction. (Moment counts, timestamp offset, batch size and tiers below come from the worker briefs, which are not stored in a file; partial support: DUMP/README.md:73-78, :111, :116.)
   - Pick: a sonnet worker reads the srt and writes SCRATCH/reports/frames-plan-<id>.md (20-30 moments: `#`, timestamp = cue start + 1 s, verbatim motivating passage, why visual). Plans exist for all four videos.
   - Grab: a haiku worker runs ffmpeg at each timestamp into DUMP/primary/S-0N-<id>/frames/<id>-HHhMMmSSs.png (30 per video), views each PNG, re-grabs at +2 s then +4 s if blank or mid-transition, writes DUMP/index/frames-<id>.md (file, timestamp, planned, passage, what the frame shows, matches expectation).
   - Extract: every PNG is read afresh by a vision worker (Read tool on the PNG) into DUMP/interleaved/extractions/S-0N/<png basename>.txt with three sections `ON-SCREEN TEXT:`, `VISUAL:`, `NOTES:`; batches of 10 PNGs per haiku worker; the index descriptions are not used as input.
5. Check and adjudication (extractions).
   - Script `check_extractions.py`: 120 PNGs vs 120 extraction files, three headings in order, non-empty sections, tallies, a seeded sample (seed 20261012, 5 per video) written to SCRATCH/reports/extraction-sample.txt.
   - A different haiku worker re-reads the sampled PNGs before opening the extraction and lists missed text, wrong words, invented elements, missed visual, wrong illegible claims (reports SCRATCH/reports/extraction-check-S-0N.md, round 1).
   - Frames with findings are re-extracted with a zoom rule (ffmpeg crop and scale, view the crop before writing `[illegible]`); round 2 and round 3 re-reads follow (extraction-check2-*, extraction-check3-S-05.md); a sonnet adjudicator re-read 11 contested frames and wrote SCRATCH/reports/extraction-adjudication.md (claims CONFIRMED / REFUTED / UNSETTLED; counts from the claim lines: 73 claims, 62 / 3 / 8).
   - Reports are archived in DUMP/interleaved/extractions/_checks/ (8 files at last count; the round-2 S-05 report is kept as `extraction-check2-S-05-stale.md`).
6. Interleaving. `build_interleaved.py` writes DUMP/interleaved/S-0N-<id>.md: header block, then one line per srt cue `[hh:mm:ss] <cue text>` in srt order, and each frame inserted after the last cue whose start is at or before the frame's timestamp as a `>` quoted block (FRAME line with PNG link, then the extraction text). `verify_interleaved.py` checks six things per document (cue texts equal the srt in order; FRAME blocks equal the PNGs, each once; links resolve; blocks equal the extraction files, compared after removing the extraction file's final newline; placement; header fields equal the provenance sidecar). Nothing is retyped by a model.
7. Index. DUMP/index/sources.md (supplied table, discovered table, cross-references found in metadata, chapters, derived files), DUMP/index/frames-<id>.md, and the tables in DUMP/README.md.
8. Manifest. DUMP/index/MANIFEST.sha256: one line `<sha256>  ./<relative path>` per file under DUMP except itself; any edited file's line is refreshed; check from DUMP with `shasum -a 256 -c index/MANIFEST.sha256` (0 failures expected). The builders and the only recorded line-refresh script (edit_manifest2.py) are in SCRATCH/work only (section 2).
9. Neutral naming, preservation and archive. Folder renamed to a name with no topic; our own topic labels replaced in non-verbatim files (content kept); README `## Preservation` at the top; DUMP/.gitignore (tracks itself, README.md, index/MANIFEST.sha256 only); tar.gz of the finished folder to ARCHIVE; sha256 sidecar; extraction test in a `mktemp -d` directory with the manifest check there; temp directory deleted; read-only git checks. The archive was rebuilt later (section 6, item 14).
