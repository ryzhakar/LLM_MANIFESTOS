## Decisions (a)-(d)

**(a) The launcher runs the bundled copy by default.** Spec line 113 says `plugin/bin/unharness` "runs the plugin's bundled copy through uvx", and spec line 112 gives the git form as the way to run before publication, outside a session. The bundled folder is `${CLAUDE_PLUGIN_ROOT}/unharness`. The git form runs only when the caller sets `UNHARNESS_FROM` to a git URL. Spec:1 proposed a fallback to git when the folder is missing; that fallback is rejected, since "only when asked" leaves the launcher no silent second path. The launcher then no longer reads the version from `plugin.json`.

**(b) Unobserved README rows state what was done, not what was shown.** Spec line 71 says B2 and D1 verify the strip set by capture, and queue 25 makes `verification-unharness.md` the one place the README cites for residue evidence. D1's report (`orchestration_log/recon/2026-10-23/d1-verification.md`) is the evidence; its verified and unverified rows are in the next block. For each unverified row the README says the switch is implemented per the Claude Code docs and the binary, and that no capture shows its text present or removed. The default cell reads "set", not "stripped".

**(c) A legacy path, URL, or hint source is refused with an error naming the `file` form, in one place.** Spec line 24 says "nothing is guessed", and spec line 35 gives the schema one home, `config.py`. So `config.py` refuses at load any `source` whose first word is not `manifesto`, `skill`, or `file`, and its message says to write `file <path>`. `unharness` stops with that message. A hook prints it as one line on stderr and exits 0, as queue 22 sets for a broken config. The hooks stop describing `http` and hint sources. Spec:4 offered "kept by the hooks, refused by unharness" or a path-to-`file` mapping; both are rejected, the first for two behaviors and the second for guessing. A bare string and a mapping without `source` stay registry names.

**(d) Hook output and skill text outrank the "not from the user" rule.** Both are the owner's standing instructions, carried by the application: the owner installed the hooks and wrote the skills. A harness notice, such as the task-list nudge and the silent-turn note, is neither, and the constitution's rules on speech govern over it. The preamble says so in that order: system-role messages are the application's, except the text of a hook's output inside them, which is the user's standing instruction, as a loaded skill's text is.
