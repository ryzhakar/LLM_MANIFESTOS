Behavior of `unharness launch [--keep-claude-md] [--keep-web-search] [--no-hooks] [PROMPT] [-- LAUNCHER [ARGS...]]`:
1. The prompt comes from the PROMPT argument, else from stdin (so `unharness prompt | unharness launch -- claude` works). An empty prompt stops with a one-line error.
2. The prompt is written to `${XDG_CACHE_HOME:-~/.cache}/unharness/<sha256 of the prompt>.md` (created with mode 0600; folder 0700).
3. The compiled command is `LAUNCHER ARGS... --system-prompt-file <that file> --disallowedTools WebSearch --settings '<json>'` with settings `{"includeGitInstructions": false, "attribution": {"commit": "", "pr": ""}, "autoMemoryEnabled": false, "outputStyle": "default"}` plus `"disableAllHooks": true` under `--no-hooks`; `--keep-web-search` drops the disallow. The environment gains `CLAUDE_CODE_ATTRIBUTION_HEADER=0 CLAUDE_CODE_DISABLE_CLAUDE_MDS=1 CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 CLAUDE_CODE_SILENT_TURN_REMINDER=0 UNHARNESS=1`; `--keep-claude-md` omits the CLAUDE_MDS variable.
4. With a launcher: run it with that environment, its stdin reopened on /dev/tty (so an interactive session gets the keyboard back after a pipe), replacing the unharness process (os.execvpe) when the launcher resolves on PATH; when it does not resolve (for example the zsh function `claude@meta`), run it through `$SHELL -ic '<quoted command>'` with the same stdin, and exit with the launcher's status. Without a launcher: print the full command as one shell-quoted line with `env` assignments in front and `</dev/tty` at the end, and run nothing.
